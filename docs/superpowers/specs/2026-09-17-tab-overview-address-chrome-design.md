# 多页面上滑时地址栏与底部工具栏联动设计

## 背景

从浏览页面上滑进入多页面标签时，当前地址栏、活动页面卡片和底部浏览器工具栏使用了同一个 `overviewProgress`，但各自通过独立的固定进度区间计算位置和透明度。结果是：

- 活动页面已经缩成卡片时，地址栏仍停留在底部工具栏上方，未贴合卡片底边。
- 地址栏与卡片底边的真实重合时刻没有参与动画决策，导致两者在中间帧出现空隙或叠压。
- 底部工具栏按照固定进度隐藏，而不是在地址栏完全离开工具栏后回弹消失。
- 卡片标题、地址栏和底部工具栏存在短暂的视觉所有权重叠。

本设计只调整浏览器页面到多页面概览的纵向转场，不改变横向切换标签、新建标签、卡片删除、历史记录或网页加载逻辑。

## 已确认的交互目标

用户已确认以下行为：

1. 上滑开始时，活动页面和地址栏共同参与页面到卡片的缩放。
2. 地址栏的可见底边持续贴合活动卡片当前底边。
3. 当地址栏完全离开底部工具栏后，底部工具栏执行一次短暂的回弹，然后在多页面停留期间保持隐藏。
4. 地址栏内容在最后阶段交给卡片标题，不能与卡片标题同时可见。
5. 从多页面退出时，卡片、地址栏和底部工具栏沿同一条轨迹反向恢复；工具栏回弹恢复可见。

## 方案选择

### 采用：统一几何轨迹

继续使用 `overviewProgress` 作为唯一时间轴，但不再用固定百分比直接决定工具栏隐藏。每一帧先生成活动页面的屏幕坐标框，再根据同一个框计算地址栏的屏幕坐标，最后用“地址栏底边是否离开底部工具栏”推导工具栏的回弹进度。

优点：

- 地址栏、活动页面和卡片使用同一组实际几何数据，不需要重新挂载 ArkWeb。
- 能处理活动卡片处在不同网格行、存在 Grid 滚动偏移或系统安全区变化的情况。
- 进入和退出只需要反向计算同一模型，减少单独动画结束时的闪帧。

### 不采用：独立动画时间轴

分别给地址栏和工具栏增加新的动画百分比可以快速调出某一帧，但无法保证不同屏幕尺寸、不同卡片行和拖动中断时仍然重合，容易再次出现当前的漂移问题。

### 不采用：把地址栏重新嵌入卡片组件

嵌入卡片可以获得局部坐标的一致性，但会改变地址栏现有的输入、命中测试和 ArkWeb 页面层级关系；短上滑回弹、退出概览和输入框焦点恢复都需要额外的节点迁移，不适合本次窄范围修复。

## 动画模型

### 1. 活动卡片框

沿用 `tabOverviewPageFrame()` 产生的屏幕坐标：

- `clipLeft`、`clipTop`、`clipWidth`、`clipHeight` 是当前活动卡片窗口。
- `scaleX`、`scaleY` 是活动页面层的实时缩放。
- 卡片底边为 `cardBottom = clipTop + clipHeight`。

地址栏的可见高度使用当前缩放后的高度。地址栏的目标顶部为：

```text
addressTop = cardBottom - addressVisibleHeight
```

中间过程只在屏幕坐标中插值一次，避免再次把已经插值过的 `pageFrame` 按 `overviewProgress` 二次插值而产生滞后。

### 2. 地址栏阶段

地址栏分为三个阶段：

| 阶段 | 条件 | 行为 |
| --- | --- | --- |
| 页面贴合 | 卡片底边尚未越过底部工具栏上沿 | 地址栏随活动页面缩放并向卡片底边靠拢 |
| 联动上移 | 地址栏底边已经完全离开底部工具栏 | 地址栏和活动卡片继续沿同一屏幕轨迹上移 |
| 标题接管 | 活动卡片达到稳定网格位置 | 地址栏透明度降为 0，卡片标题淡入 |

阶段切换不依赖固定的视觉猜测值，而是使用当前地址栏底边、底部工具栏上沿和卡片底边的几何关系。固定区间只用于回弹曲线的时间长度和标题淡入的平滑过渡。

### 3. 底部工具栏阶段

工具栏保持挂载，避免进入概览最后一帧发生重新布局：

1. 地址栏仍与工具栏相交时，工具栏保持原位置。
2. 地址栏完全离开工具栏后，触发一次短回弹：轻微拉伸，随后向屏幕底部移动。
3. 透明度降为 0，并禁用命中测试；多页面停留期间不再显示。
4. 退出概览时沿同一进度模型反向回到可见位置，保留一次轻微回弹。

工具栏的位移和透明度必须由同一 `TabOverviewChromeFrame` 输出，不能在 `BrowserShell` 另设第二套隐藏条件。

### 4. 标题与地址栏交接

活动页面的卡片标题在地址栏已经离开工具栏、且活动卡片接近稳定尺寸后淡入。地址栏先淡出，标题后淡入，保证任意帧最多只有一个文本所有者。

## 代码边界

预计修改范围：

- `app/entry/src/main/ets/browser/model/TabOverviewActions.ets`
  - 补充卡片底边、地址栏底边和工具栏上沿的几何计算。
  - 统一 `TabOverviewChromeFrame` 的地址栏联动、工具栏回弹和标题交接输出。
- `app/entry/src/main/ets/browser/components/BrowserShell.ets`
  - 继续从同一 `overviewChromeFrameForRender()` 消费工具栏和地址栏几何。
  - 保持概览期间工具栏挂载和命中测试关闭，删除与统一模型重复的条件（如发现）。
- `app/entry/src/main/ets/browser/components/AddressTabStrip.ets`
  - 只保留屏幕框架提供的布局和缩放消费，不增加第二条动画轨迹。
- `app/entry/src/main/ets/browser/components/BrowserTransitionScene.ets`
  - 仅在运行证据显示页面层与卡片框仍有错位时调整；默认不改 ArkWeb 宿主层。
- `app/entry/src/test/ets/test/TabOverviewTransition.test.ets`
  - 增加边界帧和反向退出的纯模型回归测试。

## 验收条件

### 纯模型验收

- 进度为 0 时地址栏位置与现有页面位置一致，工具栏完全可见。
- 任意中间进度，地址栏底边与活动卡片底边的误差不超过 1vp（允许标题交接阶段透明度变化）。
- 地址栏完全离开工具栏后，工具栏开始回弹；达到概览终点时工具栏透明度为 0、位移在屏幕底部之外、命中测试关闭。
- 概览终点地址栏透明度为 0、标题可见；退出概览时两者反向恢复且不出现双文本。
- Grid 滚动偏移变化、活动标签位于不同网格行时，地址栏仍贴合活动卡片而不是贴合屏幕固定位置。

### 运行验收

在 Mate 80 模拟器上使用新构建的 HAP 验证：

1. 单个起始页上滑进入多页面。
2. 多个标签页上滑进入多页面，活动卡片在第一行和较低行各验证一次。
3. 慢速上滑、快速上滑、上滑中途松手回弹。
4. 在多页面停留确认底部工具栏持续隐藏，再点击卡片退出确认工具栏回弹恢复。
5. 采集转场中帧和终态截图、布局树和 `overviewProgress`/工具栏/地址栏日志，确认视觉结果与几何模型一致。

## 非目标与风险

- 不把底部工具栏永久从视图树中移除，避免短手势回弹时产生首帧闪烁。
- 不通过截图替代 ArkWeb 页面层；页面仍由现有 live page transform 驱动。
- 系统安全区、窗口高度和卡片滚动偏移必须参与计算，否则仅在当前模拟器分辨率上正确。
- 本文档和视觉草图只定义交互时序，最终 vp 参数以运行截图和布局证据为准。
